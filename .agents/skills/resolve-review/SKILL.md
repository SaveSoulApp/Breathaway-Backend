# Resolve AI Review Findings (`/resolve-review`, `/fix-review`)

This skill provides an automated, structured workflow to address and resolve all issues identified during an AI code review (such as [.agents/skills/ai-review/SKILL.md](file:///.agents/skills/ai-review/SKILL.md) or `/ai-review`).

It works through **Potential Bugs**, **Security Concerns**, **Performance Concerns**, **Maintainability issues**, and **Suggested Improvements** while strictly enforcing the project's NestJS, Prisma, GCP, and domain event constraints.

---

## Slash Commands & Triggering

Users can trigger this skill using:

- `/resolve-review`
- `/fix-review`
- _"Lets work on the suggested improvement to solve the Potential bugs, Security Concerns, Performance Concerns and Maintainability"_
- _"Fix the issues identified in the AI review"_
- _"Apply review findings"_

---

## Non-Negotiable Constraints & Architecture Rules

Before making any changes, uphold all project architectural standards:

1. **Environment File Blacklist**: NEVER read, edit, touch, create, or commit `.env`, `.env.local`, `.env.development`, or `env.dev.yaml`. Use NestJS `ConfigService` for all configurations.
2. **No Destructive Database Actions**: NEVER run `prisma migrate dev` or `prisma db push` directly. If schema alterations are required, output the exact command for the user to run manually.
3. **Decoupled Notifications Architecture**:
   - Feature services must **never** import `NotificationsModule` or inject `NotificationsService`.
   - Feature services must **never** query `prisma.userProfile` solely to fetch recipient details for notifications.
   - Services extending `BaseService` inherit `this.eventEmitter: EventEmitter2`. Emit strongly typed domain events.
4. **External HTTP**: NEVER use direct `axios`. Inject and use `HttpClientService` from `@infrastructure/http`.
5. **Mandatory 4-Group Imports**:
   1. Built-in Node modules
   2. External npm packages
   3. Internal absolute path modules (`@modules/...`, `@infrastructure/...`, `@core/...`, `@common/...`, `@shared/...`)
   4. Local relative paths (`./dto/...`, `./entities/...`)
   - **Absolute Path Rule**: Any import traversing > 2 levels (`../../../`) MUST use absolute `@...` path aliases.
   - Run `npx prettier --write <file>` on modified files.
6. **Iteration Budget**: Max 3 repair iterations for fixing TypeScript/ESLint errors.

## Execution Protocol

### Step 1: Review Finding Ingestion

Locate review findings from:

1. **Conversation Context**: Recent `/ai-review` output under `## Potential Bugs`, `## Security Concerns`, `## Performance Concerns`, `## Maintainability`, `## Suggested Improvements`.
2. **Artifact File**: `.agents/review.md` (if generated by review scripts).
3. **Git Diff**: Changes against `origin/develop` via `.agents/skills/ai-review/scripts/extract-pr-diff.sh --base origin/develop --stat`.
4. **User Prompt**: Direct user-pasted findings or PR comments.

### Step 2: Prioritized Remediation Plan

Group findings in descending risk order:

1. 🚨 **Security Concerns** (Authentication, Authorization/IDOR, SQL injection, secrets, log sanitization)
2. 🐛 **Potential Bugs** (Logic errors, edge cases, race conditions, regex traps, nullability)
3. ⚡ **Performance Concerns** (N+1 queries, missing transactions, unindexed lookups)
4. 🧹 **Maintainability & Suggested Improvements** (4-group imports, absolute paths, decoupling notifications, DTO validation, dead code)

Present the categorized checklist to the user.

### Step 3: Implement Fixes

- Apply clean, minimal changes maintaining code documentation.
- Adhere strictly to SRP, DI, and DTO architecture.
- Format with `npx prettier --write <file>`.

### Step 4: Update Unit Tests

- Update or create `<file>.spec.ts` for modified services.
- Test bug fixes, security authorization checks, and domain event emissions.
- Mock `EventEmitter2` and `HttpClientService` (never `axios`).
- Run `pnpm exec jest <path-to-spec>`.

### Step 5: Verification & Quality Gates

- TypeScript: `pnpm exec tsc --noEmit`
- Linter: `pnpm lint`
- Tests: `pnpm exec jest --passWithNoTests`

### Step 6: Summary & Hand-off

- Output a markdown remediation summary table.
- Recommend running `/prepare-for-pull-request` to run full CI quality checks before committing or opening a pull request.
